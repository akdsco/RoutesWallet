# map-match — snap road routes to the road network (Valhalla)

Worktree for **TB-46**. Data pipeline only — no UI changes.

- TB-46: https://app.notion.com/p/Map-match-road-routes-to-the-road-network-Valhalla-for-pixel-perfect-lines-3b415f963d13811f9a33f15f1e384712
- Base: `main` @ a808ca4

## Problem

Some road routes' GPX lines look slightly jumpy / off the road. Map-match the
**road** routes to the road network (e.g. **Valhalla** `trace_route` /
map-matching) so the lines sit pixel-perfect on the roads, then regenerate
`public/routes.geojson`.

## ⚠️ Hard constraints
- **Never snap gravel / off-road routes onto roads** — that would falsify them.
  Exclude them (by `route_type` and/or a per-route opt-out). If in doubt, leave a
  route un-matched.
- **Keep full resolution — never drop points.** Quality bar is high (this was an
  explicit past decision). Map-matching must not decimate.
- It's a pipeline/data change: a script + a regenerated `routes.geojson`. Diff the
  before/after visually before committing.

## Key files

- `web/public/routes.geojson` — regenerated output

## Implementation (2026-08-09)

**Approach** — offline map-match via the public **FOSSGIS Valhalla** instance
(`trace_route`, `costing: bicycle`, `shape_match: map_snap`). No dependency added,
no key, no server: a `vite-node` script that imports tested pure helpers from
`src/lib`. Node 24 global `fetch`.

**Eligibility (never falsify gravel).** Match only `route_type: 'Road'` minus two
off-road routes that carry a Road tag (`Strade Bambini - 70km`, `Blackmore 80km
(with gravel section)`) — together with the 9 `Gravel`-tagged, that's the ticket's
11 excluded. The 32 untyped (club-member) routes are left un-matched ("in doubt,
leave"). 82 routes eligible.

**Chunking.** Valhalla `map_snap` truncates a whole route at the first unroutable
spot (a single-shot run matched only ~42% of routes end-to-end). So each long route
is matched in **~300-point shared-boundary chunks** (`chunkTrace`), each chunk
gated on coverage (≥95%), then **stitched** (`stitchChunks`, seam-dedupe). A bad
spot costs only its own chunk (raw fallback for that segment); a route is kept
fully raw if <60% of its chunks match. Short routes (≤300 pts) use a single request
with the strict `acceptMatch` gate (coverage + length deviation).

**Quality / safety.**
- Full resolution preserved — output is Valhalla's road geometry (denser than the
  ~48 m GPS input: e.g. 874 → 1759 pts), never decimated. Normalised to 6 dp.
- Bad matches fall back to raw, never ship. `distance_km`/contract shape untouched.
- Raw kept as `public/routes.raw.geojson` (pristine snapshot; also the matching
  input, so re-runs are idempotent). Not served by the app.
- Checkpoints every 3 routes + `--resume` so a ~15-min run survives interruption.

**Files.** `src/lib/mapMatch.ts` (+ tests, 23 cases) · `scripts/map-match.ts`
(runner) · `scripts/map-match-diff.html` (dev-only before/after overlay for
spot-checking) · regenerated `public/routes.geojson` + `scripts/map-match-report.json`.
