# map-match — snap road routes to the road network (Valhalla)

Worktree for **TB-46**. Data pipeline only — no UI changes.

- TB-46: https://app.notion.com/p/Map-match-road-routes-to-the-road-network-Valhalla-for-pixel-perfect-lines-3b415f963d13811f9a33f15f1e384712
- Base: `main` @ a808ca4

## Problem

Some road routes' GPX lines look slightly jumpy / off the road. Map-match the
**road** routes to the road network (e.g. **Valhalla** `trace_route` /
map-matching) so the lines sit pixel-perfect on the roads, then regenerate
`public/routes.geojson`.

## ⚠️ Hard constraints
- **Never snap gravel / off-road routes onto roads** — that would falsify them.
  Exclude them (by `route_type` and/or a per-route opt-out). If in doubt, leave a
  route un-matched.
- **Keep full resolution — never drop points.** Quality bar is high (this was an
  explicit past decision). Map-matching must not decimate.
- It's a pipeline/data change: a script + a regenerated `routes.geojson`. Diff the
  before/after visually before committing.

## Key files
- `web/scripts/*` — a new map-match script (see existing import scripts for style)
- `web/public/routes.geojson` — regenerated output
- No `web/src` changes.

## Implementation (2026-08-09)

**Approach** — offline map-match via the public **FOSSGIS Valhalla** instance
(`trace_route`, `costing: bicycle`, `shape_match: map_snap`). No dependency added,
no key, no server: a `vite-node` script that imports tested pure helpers from
`src/lib`. Node 24 global `fetch`.

**Eligibility (never falsify gravel).** Match only `route_type: 'Road'` minus two
off-road routes that carry a Road tag (`Strade Bambini - 70km`, `Blackmore 80km
(with gravel section)`) — together with the 9 `Gravel`-tagged, that's the ticket's
11 excluded. The 32 untyped (club-member) routes are left un-matched ("in doubt,
leave"). 82 routes eligible.

**Chunking + context margins.** Valhalla `map_snap` truncates a whole route at the
first unroutable spot, so routes are matched in **300-point cores** (`chunkTrace` →
`chunkWithMargins`). A bare chunk lets the matcher invent a detour near its edge
(no context), so each core carries an **80-point margin** each side for matching
and is trimmed back to its core afterward (`coreFromMatch`), then **stitched**
(`stitchChunks`). We match via **`trace_attributes`** (not `trace_route`) because
its `matched_points` give one snapped position per input point — that's what lets
us trim to the core exactly.

**The hard finding — map-matching this data can't be made fully clean.** Snapping
produces a MIX that no automated gate can separate:
- *Corrections* — raw sometimes cuts a straight diagonal across fields / drifts off
  the road; matching fixes it (good).
- *Mis-snaps* — at complex junctions the matcher snaps onto a neighbouring road /
  residential loop the route never used (bad). Not a chunk artifact — `trace_route`,
  `trace_attributes`, margins, and `costing:auto` all still do it.

Both read as large stray-from-raw, so we can't keep one and drop the other.

**Decision (user, 2026-08-09) — ship the safe subset.** The ticket's real goal is
"lines sit a *few metres* off the road" = the small on-road nudges, which are safe
(a <~35 m move can't jump to a different road). So a **60 m stray gate**
(`maxStrayMeters`, point-to-point) keeps only those and reverts *every* big mover —
mis-snap OR large correction — to the vetted raw line. Result: **49 matched /
33 reverted to raw / 43 excluded** (9 gravel + 2 named off-road + 32 untyped).

**Quality / safety.**
- Full resolution preserved — output is Valhalla's road geometry (denser than the
  ~48 m GPS input), never decimated. Normalised to 6 dp.
- Every reverted / excluded route is **byte-identical to raw** (verified). Contract
  shape + `distance_km` untouched.
- Raw kept as `public/routes.raw.geojson` (pristine snapshot; also the matching
  input, so re-runs are idempotent). Not served by the app.
- Checkpoints every 3 routes + `--resume` so a ~15-min run survives interruption.

**Files.** `src/lib/mapMatch.ts` (+ tests, 32 cases) · `scripts/map-match.ts`
(runner) · `scripts/map-match-diff.html` (dev-only before/after overlay, with a
scripted single-route focus) · regenerated `public/routes.geojson` +
`scripts/map-match-report.json`.

**Follow-up (not this PR):** TB-58 road/gravel search filter (surfacing
`route_type` in the UI) — split out; a separate feature, not this data change.
