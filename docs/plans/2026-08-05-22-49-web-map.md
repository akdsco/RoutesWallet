# web map

- Date: 2026-08-05 22:49
- Branch: web-map

## Problem / Context

RoutesWallet's original vision (sync-everything + social) is blocked/undefensible:
Strava's Nov-2024 API terms forbid showing one user's routes to another, Garmin is
push-only, Komoot is a closed paywalled silo. Only RideWithGPS has an open API.

The validated wedge (from the user's own club WhatsApp: ~30 "route near X?" asks in
16 months, Girona asked 3×, a stale club route library nobody can search) is much
narrower: **a map that shows all the club's routes and lets you search "routes near
a place".** No app-store, no backend, no subscription needed to validate it — it's a
static web page. That sidesteps the Apple $99 fear entirely and costs ~£0 to run.

This branch restructures the repo into a loose monorepo (parked RN app → `mobile/`,
new web map → `web/`) and scaffolds the web map. No workspaces — the two apps share
no code, so hoisting/Metro surgery would be pure risk. Everything in the RN app is
relative (`__dirname`, `./app/...`), so a wholesale folder move is safe.

## Plan

- Loose monorepo: `mobile/` (existing Expo/RN app, history preserved via `git mv`)
  + `web/` (new Vite + React + TS map). Each self-contained, own `node_modules`.
- Web stack: Vite + React + TypeScript (strict), Leaflet + OSM raster tiles,
  Turf.js for the "near X" distance filter, static `routes.geojson` data.
- Frozen v1 scope — ONE screen, THREE behaviours: (1) show all routes on a map,
  (2) search "near <place>" to filter, (3) click a route to open its existing link.
- Frozen route data contract:
  `{ id, name, link, distance_km, source: "HV-signed" | "3rd-party", geometry:
  LineString, centroid: [lng, lat] }`.
- Non-goals (NOT in v1): accounts, mobile app, send-to-device, follow/social graph,
  cafe/winter metadata, monetisation, any server.
- Test-first for pure logic only (near-X filter, geocode/parse); map/UI by eye.

3. **Scaffold `web/`.** impl: Vite + React + TS (strict), Leaflet + Turf deps,

4. **Route data contract + near-X filter (RED→GREEN).** test: `routesNear(point,
   routes, radiusKm)` returns routes whose line passes within radius, sorted by
   proximity; excludes far ones. impl: Turf `pointToLineDistance` over GeoJSON.
   commit.
5. **Map screen.** impl: Leaflet map drawing all routes; click → popup w/ name +
   open link; `source` badge. verify by eye (seeded real routes). commit.
6. **Search "near <place>".** impl: search box → geocode (Nominatim or static
   gazetteer) → point → `routesNear` → highlight/filter on map + list. commit.
7. Seed 3–4 real routes (Girona / Cambridge) as `routes.geojson`. Push, open PR.
