## Problem

The app is desktop-first: a fixed 392px sidebar next to the map. On a phone the
sidebar takes the whole screen, the map is a ~30px sliver, and the page scrolls
sideways — **effectively unusable**. Since the app is shared as a link
(WhatsApp → phones), this is high impact.

Make it responsive. **Pattern 1a (recommended):** map full-screen + a draggable
**bottom sheet** holding search + the route list (Google-Maps style).
**Alternative 1b:** a list/map toggle. Desktop layout stays as-is above a
breakpoint.

## Decision — Pattern 1a (bottom sheet), per Claude Design's A-D spec

Design verdict: bottom sheet, not the List/Map toggle. The heatmap is the novel
thing; a toggle hides it half the session and forces a mode choice too early. 1b's
simplicity is recovered by making the handle a **button** (every snap tap-reachable).

Concrete numbers (supersede the ticket's 30/62/92%):
- Snaps: **peek 132px** (header + one card), **mid 56dvh**, **full 100dvh − 132px**
  (map strip always visible). `dvh` + `vh` fallback + `env(safe-area-inset-bottom)`.
- Gestures: drag handle/header; release velocity > 0.5px/ms → next snap, else
  nearest. Transform-only, 220ms `cubic-bezier(.32,.72,0,1)`.
- Handle is a real `<button>` (44px hit): tap cycles peek→mid→full→peek,
  `aria-expanded` + next-stop label; Enter/Space cycles, Esc from full → mid.
- Selection → snap **peek**, pin selected card to top, pan map; Open becomes a
  full-width **48px** button. Search resolves → auto-snap **mid**.
- `role="dialog" aria-modal="false"`. Reduced motion: snaps jump, map pans instant.
- Breakpoints: ≥1024 desktop (392px list) · 768–1023 desktop (320px list) · <768 sheet.

Overlay fates (<768): legend keep+shrink; POI chips → sheet header (scroll row,
44px hit); hover card cut; zoom±/z-badge cut (pinch native, keyboard +/− kept);
attribution → sheet footer; search states render in the sheet.

### Out of scope here (flagged, not built)
- **Basemap switcher + CyclOSM** (spec §C) — new feature, not in the app today. No
  mobile "layers" button. Future ticket.
- **Context-aware legend key-swap** (§A) — also changes desktop; do mobile
  reposition/shrink only, defer the idle↔search swap.
- **Card focus≠selection + exact search copy** (§D) — that's **TB-47**. Touch only
  the mobile full-width Open button (additive), as the anchor landing first.
- Design's "say no" list: geolocation, PWA/offline, sort/filter, elevation.
