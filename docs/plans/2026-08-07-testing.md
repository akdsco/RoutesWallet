## Problem

Unit tests + CI already exist and are solid: `web CI` runs typecheck → lint →
format:check → **117 Vitest unit tests** on every PR, covering the pure logic in
`web/src/lib`. Missing: the two layers above.

- **Integration (Testing Library + jsdom):** App/Sidebar flows — search → matches
  + 25 km radius, postcode search, geofail/no-match banners, select route → link,
  theme toggle, POI chips, aria-live announcements. **Select by role, assert on
  semantics** (repo convention). Leaflet is canvas/DOM-heavy — assert on React
  state + surrounding DOM (mock the map where needed), not pixels.
- **E2E (Playwright):** critical journeys in a real browser — map loads, search a
  place + a UK postcode → radius + matches, click a route → "Open in Strava",
  theme flip, prefers-reduced-motion. Consider running against a Cloudflare Pages
  preview deploy.
- **CI:** keep unit tests as the fast gate; add a separate (slower) E2E job with
  cached Playwright browsers.

## How to work here
- `cd web && npm ci` first.
- Full gate before push: `npm run typecheck && npm run lint && npm run format:check && npm test && npm run build`.
- Open a PR into `main` when done — the user merges.
